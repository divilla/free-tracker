## 1. Brief

Create the first buildable Flutter Android application and its executable reference architecture. Demonstrate feature ownership, composition, a framework-independent domain/application slice, constructor-injected I/O, SDK-to-domain conversion, and meaningful failure/recovery tests. This is code that later changes extend, not empty folders or a disposable demo.

The publisher approved a minimal **app-information slice** during authoring: plain-Dart app metadata, an injected loader, a thin platform adapter, and localized loading/success/error/retry UI. Full Settings/About remains S019. This slice reads installed application metadata; it does not simulate working tour recording.

**Authoring baseline evidence:** the working tree was clean before this document; only `agent/changes/000-initial-commit.md` existed. At authoring there was no `lib/`, `android/`, `pubspec.yaml`, root Makefile, or app/unit/E2E suite. A root Makefile has since been added; both targets report unavailable and exit 2 until genuine runners/suites exist. The app remains absent. Existing `scripts/` contains user-owned workflow helpers and tests; their IMPLEMENT conformance is not established. For example, `scripts/makefile_test.sh` references another application's Go/PostgreSQL/frontend targets, so it is not evidence of Flutter runner correctness. Preserve existing tooling; S003–S004 own its audit/adaptation. S001 must add isolated app-test tooling without replacing workflow scripts.

All source paths, test identifiers, commands, and artifacts below describe **planned implementation**, not files or passing tests already present. D01 is now resolved by publisher confirmation: use `com.bindefined.freetracker`. Do not generate an app using a temporary or invented publisher ID. This confirmation does not establish build or test success.

## 4. Contracts

### Executable reference architecture

Implement these reference locations; they are intentionally new at this baseline. S001's implementation updates the guidance if a justified filename change is needed, preserving the stable requirement/case/test identifiers and traceability. Do not create empty `recording/measurement` or `tours/domain` modules: the settings slice demonstrates the plain-Dart boundary that those modules must later follow, without inventing their contracts.

| Planned location | Responsibility and dependency contract |
| --- | --- |
| `lib/main.dart` | Initialize Flutter binding and invoke the single production composition root; no feature rules or fixture switch. |
| `lib/app/app.dart`, `lib/app/composition.dart` | Shell/theme/localization and dependency construction; support constructor-supplied feature dependencies for tests without runtime debug menus. |
| `lib/settings/domain/app_info.dart` | Immutable validated metadata and language-independent failure/result types, plain Dart only. Validation is meaningful protection against invalid/wrong-app metadata, not a folder-layout exercise. |
| `lib/settings/application/app_info_repository.dart` | Narrow `Future<AppInfoResult> load()` port; success contains validated `AppInfo`, failure contains `invalidMetadata`, `unsupportedPlatform` or `readFailed`. |
| `lib/settings/application/app_info_loader.dart` | Plain-Dart load/coalescing/retry/close state holder, constructed with the repository. Owns feature asynchronous state, not a trivial call-forwarding use-case class. |
| `lib/settings/data/platform_app_info_repository.dart` | Only layer importing the metadata SDK. Inject a reader function at construction for deterministic SDK fixtures; production uses the real platform read. Convert immediately at the boundary. |
| `lib/settings/presentation/app_info_screen.dart` | Render state and forward Retry; no plugin calls, metadata validation, durable state or recording owner. |
| `lib/l10n/app_en.arb`, `l10n.yaml` | English messages with generated Flutter localization bindings; generated path is explicitly configured and documented. |
| `Makefile`, `tool/run_tests.py`, `tool/check_coverage.py`, `tool/check_scaffold.py` | App-only runners, coverage and reference/configuration checks; no workflow/merge implementation. |
| `agent/reference-scaffold.md` | Implementation-authored extension/stack/identity/evidence guide with links to actual code and tests. |

### Interfaces, state and ordering

- Configure the expected publisher ID in composition from the confirmed build identity; domain/application never read ambient platform state. No user-entered identity field is added. Installation metadata is read-only; no network or permission request is needed by this slice.
- Domain validation checks trimmed nonempty fields, exact configured identity/name, and a build-number string consisting solely of digits with numeric value greater than zero. Keep version/build identifiers as strings so formatting does not localize or round them. Leading zeroes in an otherwise positive build string are valid and preserved; blank/zero/negative/decimal/nonnumeric strings are invalid. Version is a nonblank opaque display string, not a new semantic-version policy. No guessed version such as `0.0.0` on error.
- `AppInfoLoader` exposes a current immutable state and an observable stream/equivalent subscription of `idle`, `loading`, `ready(AppInfo)` or `unavailable(code)`, with `load()`/`retry()` and `close()`. Construction is idle; shell startup calls load once. The implementation selects and documents one consistent presentation binding under D05; it must preserve this plain-Dart feature contract.
- Idle or unavailable → loading → ready/unavailable. Loading → load/retry does not launch a second reader. Ready → load is a no-op for this slice; no refresh feature is added. Retry from unavailable clears the prior failure while pending. Failure never retains a successful payload. No automatic retry loop, timestamps, tour timer, sensor ordering, calibration or recording-state semantics are introduced.
- The repository normally returns typed results. An unexpected thrown repository error is defensively converted by the loader to `unavailable(readFailed)`, with no raw exception in feature state and no stuck in-flight flag. Explicit Retry remains possible.
- Close is idempotent, disallows further loads without invoking I/O, closes state subscriptions once and ignores pending completion; no late success/error publication or unhandled asynchronous exception. There is only one in-flight feature read, not a service-backed recording owner.

Installed metadata is loaded afresh after process recreation; no cached-success durability claim is made. SQLite binding/harness belongs to S005, production schema/migrations to S009. Do not use an in-memory/JSON metadata example as a substitute for the confirmed SQLite product requirement. Real SQLite transaction/recovery/migration checks are N/A to S001 only because no storage behavior is introduced; they remain required for applicable later changes.
